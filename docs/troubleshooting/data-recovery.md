## 预防措施

预防胜于治疗！以下措施可以帮助您避免数据丢失：

### 定期备份

1. **自动备份**: 在插件设置中启用"自动备份"
2. **手动备份**: 定期使用"导出数据"功能
3. **备份频率**: 建议至少每周一次

### 备份位置

- **本地备份**: 保存到您的电脑
- **云备份**: 同步到云盘（Dropbox、Google Drive、OneDrive 等）
- **多位置**: 同时保存到多个位置

### 版本历史

FlowUs 自动保存版本历史：

1. 在 FlowUs 中打开数据库
2. 点击"..."菜单
3. 选择"版本历史"
4. 查看和恢复旧版本

## 常见数据问题

### 数据误删除

**症状**: 某些 TODO 不见了

**可能原因**:
- 误操作删除
- 同步时被覆盖
- 冲突解决策略导致

### 数据损坏

**症状**: TODO 显示乱码或格式错误

**可能原因**:
- 特殊字符处理错误
- 同步中断导致部分写入
- 数据格式不兼容

### 数据不同步

**症状**: Obsidian 和 FlowUs 中的数据不一致

**可能原因**:
- 同步失败
- 网络中断
- 冲突未正确处理

### 数据丢失

**症状**: 所有数据都不见了

**可能原因**:
- 重置缓存
- 卸载插件
- 磁盘故障

## 从 FlowUs 恢复

FlowUs 是您的数据主备份，优先尝试从 FlowUs 恢复。

### 方法一：重新同步（最简单）

1. 在 Obsidian 中打开插件设置
2. 点击"重置缓存"按钮
3. 确认重置
4. 点击"立即同步"按钮
5. 等待同步完成

这会从 FlowUs 重新拉取所有数据。

### 方法二：检查 FlowUs 回收站

1. 登录 FlowUs
2. 点击左侧菜单的"回收站"
3. 查找是否有删除的数据库或页面
4. 如果有，右键点击选择"恢复"

### 方法三：使用 FlowUs 版本历史

1. 在 FlowUs 中打开数据库
2. 点击右上角的"..."菜单
3. 选择"版本历史"
4. 查看历史版本列表
5. 找到数据正常的版本
6. 点击"恢复此版本"

### 方法四：从 FlowUs 导出再导入

1. 在 FlowUs 中打开数据库
2. 点击"..."菜单
3. 选择"导出"
4. 选择导出格式（CSV 或 JSON）
5. 保存导出文件
6. 在 FlowUs 中创建新数据库
7. 导入刚才的导出文件
8. 在插件设置中更新 Database ID

## 从本地备份恢复

如果您之前有导出过数据，可以从备份文件恢复。

### 查找备份文件

备份文件可能在以下位置：

- **下载文件夹**: `~/Downloads/` 或 `C:\Users\您的用户名\Downloads\`
- **文档文件夹**: `~/Documents/` 或 `C:\Users\您的用户名\Documents\`
- **桌面**: `~/Desktop/` 或 `C:\Users\您的用户名\Desktop\`
- **Obsidian 插件文件夹**: `插件目录/flowus-limbic/backups/`

### 从 JSON 备份恢复

1. 在 Obsidian 中打开插件设置
2. 找到"导入数据"按钮
3. 点击按钮，选择您的 JSON 备份文件
4. 确认导入
5. 等待导入完成
6. 点击"立即同步"，将数据推送到 FlowUs

### 从 CSV 备份恢复

1. 在 FlowUs 中创建新数据库
2. 设置正确的字段（title、completed 等）
3. 点击"..."菜单 → "导入"
4. 选择您的 CSV 文件
5. 映射字段
6. 完成导入
7. 在插件设置中更新 Database ID
8. 在 Obsidian 中重置缓存并重新同步

## 从导出文件恢复

### 使用插件导出功能

如果您定期使用插件的"导出数据"功能：

1. 找到最新的导出文件（.json）
2. 在 Obsidian 中打开插件设置
3. 点击"导入数据"
4. 选择导出文件
5. 确认导入
6. 验证数据是否完整
7. 同步到 FlowUs

### 导入选项

导入时会有以下选项：

| 选项 | 说明 |
|------|------|
| **覆盖所有数据** | 删除现有数据，导入新数据 |
| **合并数据** | 保留现有数据，添加新数据 |
| **仅添加新数据** | 只导入不存在的数据 |

建议：先使用"合并数据"，确认无误后再考虑"覆盖所有数据"。

## 修复损坏的数据

### 识别损坏的数据

损坏的数据可能表现为：
- TODO 标题显示为 `undefined` 或 `null`
- 日期显示异常
- 特殊字符显示为乱码
- 无法编辑或删除

### 修复步骤

1. **导出当前数据**: 即使数据损坏，也先导出备份
2. **在 FlowUs 中修复**:
   - 直接在 FlowUs 中编辑损坏的记录
   - 或删除损坏的记录，重新创建
3. **在 Obsidian 中重置缓存**:
   - 插件设置 → "重置缓存"
   - 重新同步
4. **验证数据**: 确认所有数据正常

### 使用文本编辑器修复 JSON

如果导出的 JSON 文件损坏：

1. 用文本编辑器（VS Code、Sublime Text 等）打开 JSON 文件
2. 检查 JSON 格式是否正确：
   - 所有引号是否闭合
   - 逗号是否正确
   - 大括号和中括号是否匹配
3. 使用 JSON 验证工具：
   - https://jsonlint.com/
   - VS Code 内置 JSON 验证
4. 修复发现的错误
5. 保存文件
6. 尝试重新导入

## 紧急恢复步骤

如果您遇到紧急数据丢失，请按以下步骤操作：

### 第一步：保持冷静

- ❌ 不要慌张
- ❌ 不要立即进行可能破坏数据的操作
- ✅ 先停止所有同步操作
- ✅ 立即导出当前状态（即使看起来有问题）

### 第二步：检查 FlowUs

1. 登录 FlowUs
2. 打开您的数据库
3. 确认数据是否还在
4. 如果在：恭喜！FlowUs 有完整数据
5. 如果不在：检查回收站

### 第三步：从 FlowUs 恢复

如果 FlowUs 有完整数据：

1. 在 Obsidian 插件设置中
2. 点击"重置缓存"
3. 确认重置
4. 点击"立即同步"
5. 等待同步完成
6. 验证数据

### 第四步：检查本地备份

如果 FlowUs 也没有数据：

1. 查找您是否有导出的备份文件
2. 查找是否有自动备份
3. 检查云盘是否有同步的备份
4. 检查电脑的回收站/废纸篓

### 第五步：使用版本历史

如果有 FlowUs 版本历史：

1. 在 FlowUs 中打开数据库
2. 点击"..." → "版本历史"
3. 找到数据正常的时间点
4. 恢复该版本
5. 在 Obsidian 中重置缓存并同步

### 第六步：寻求帮助

如果以上步骤都无法恢复：

1. 收集所有信息：
   - 问题发生的时间
   - 您做了什么操作
   - 您尝试过的恢复步骤
   - 任何错误信息
   - 您拥有的备份文件
2. 提交 [GitHub Issue](https://github.com/yourusername/FlowUs-Limbic/issues)
3. 联系 FlowUs 支持（如果是 FlowUs 端的问题）

## 恢复后的验证

恢复数据后，请验证：

1. **数量检查**: TODO 数量是否正确
2. **内容检查**: 随机抽查几个 TODO 的内容
3. **完整性检查**: 确认所有字段（优先级、截止日期等）都正常
4. **同步检查**: 创建一个测试 TODO，确认可以同步到 FlowUs
5. **备份**: 立即创建新的备份！

为了避免将来的数据问题，建议：

- [ ] 使用云盘自动同步备份文件夹

### 多副本策略

- [ ] 本地保留最近 7 天的备份
- [ ] 云盘保留最近 30 天的备份
- [ ] 定期归档长期备份

### 测试恢复

- [ ] 每月测试一次恢复流程
- [ ] 确认备份文件可用
- [ ] 熟悉恢复步骤
