# FlowUs 开发者中心配置指南

## 概述

本指南将详细介绍如何在 FlowUs 开发者中心创建应用并配置相关设置，以便与 FlowUs Limbic 插件进行集成。

## 访问开发者中心

1. 打开浏览器，访问 [FlowUs 开发者中心](https://api.flowus.cn/)
2. 使用您的 FlowUs 账户登录
3. 首次登录可能需要完成开发者注册流程

## 创建新应用

### 1. 基本信息设置

1. 登录后，点击"创建应用"或"新建应用"按钮
2. 填写应用基本信息：
   - **应用名称**：FlowUs Limbic
   - **应用描述**：Obsidian 与 FlowUs 数据库同步工具，实现双向实时同步
   - **应用类型**：选择"Web 应用"或"桌面应用"
   - **应用图标**：可以上传应用图标（可选）

### 2. OAuth 配置

1. 在应用设置中，找到"OAuth 配置"部分
2. 配置以下参数：
   - **授权模式**：选择"Authorization Code"
   - **授权范围**：选择"all"或根据需要选择特定权限
   - **重定向 URI**：设置为 `obsidian://flowus-limbic-callback`
   - **访问令牌有效期**：建议设置为 1 小时
   - **刷新令牌有效期**：建议设置为 30 天

### 3. 安全设置

1. 在"安全设置"部分：
   - 启用"PKCE"（推荐）
   - 设置"状态参数"验证
   - 配置"IP 白名单"（如有需要）

## 获取应用凭证

创建应用后，您将获得以下凭证：

1. **Client ID**：应用标识符，用于识别您的应用
2. **Client Secret**：应用密钥，用于验证应用身份
3. **应用 ID**：应用在 FlowUs 系统中的唯一标识

### 重要提示

- Client Secret 是敏感信息，请妥善保管
- 不要在客户端代码中暴露 Client Secret
- 定期轮换 Client Secret 以提高安全性

## API 权限配置

FlowUs Limbic 插件需要以下 API 权限：

1. **数据库读取权限**：读取 FlowUs 数据库内容
2. **数据库写入权限**：创建、更新、删除数据库记录
3. **用户信息权限**：获取基本用户信息

在开发者中心的"权限管理"部分，确保为您的应用授予这些权限。

## 数据库配置

### 1. 创建数据库

1. 登录 FlowUs 主应用
2. 创建一个新的数据库用于 TODO 管理
3. 设置数据库结构，确保包含以下字段：
   - `title`（标题）：文本类型
   - `completed`（完成状态）：复选框类型
   - `description`（描述）：文本类型（可选）
   - `priority`（优先级）：选择类型（可选）
   - `dueDate`（截止日期）：日期类型（可选）

### 2. 获取数据库信息

1. 打开创建的数据库
2. 在浏览器地址栏中找到数据库 ID
3. 记录数据库 ID 和表名，这些信息将用于插件配置

## 测试应用

### 1. 使用 OAuth 测试工具

FlowUs 开发者中心提供了 OAuth 测试工具：

1. 在应用详情页找到"测试工具"部分
2. 输入重定向 URI：`obsidian://flowus-limbic-callback`
3. 点击"测试授权"按钮
4. 验证授权流程是否正常工作

### 2. API 调试

1. 使用开发者中心提供的 API 调试工具
2. 测试数据库读取和写入操作
3. 验证权限配置是否正确

## 应用发布

### 1. 提交审核

完成开发和测试后，可以提交应用审核：

1. 在应用详情页点击"提交审核"
2. 填写审核说明：
   - 应用用途和功能描述
   - 目标用户群体
   - 数据使用和隐私保护措施

### 2. 审核流程

1. FlowUs 团队将在 3-5 个工作日内完成审核
2. 审核通过后，应用将获得生产环境访问权限
3. 审核未通过时，请根据反馈修改应用并重新提交

## 常见问题

### Q: 重定向 URI 配置错误怎么办？

**A**: 请确保重定向 URI 完全匹配 `obsidian://flowus-limbic-callback`，包括协议和路径。注意：
- 必须使用 `obsidian://` 协议
- 不能有多余的斜杠或参数
- 大小写敏感

### Q: 权限不足错误？

**A**: 请检查以下几点：
1. 确认应用已获得必要的 API 权限
2. 检查用户是否已授权相应的权限范围
3. 验证数据库是否对应用可见

### Q: Client Secret 泄露怎么办？

**A**: 立即采取以下措施：
1. 在开发者中心重置 Client Secret
2. 更新插件配置中的 Client Secret
3. 检查访问日志，确认是否有异常访问
4. 考虑撤销所有已发放的访问令牌

## 最佳实践

### 1. 安全性

- 定期轮换 Client Secret
- 使用最小权限原则，只申请必要的 API 权限
- 启用所有可用的安全功能，如 PKCE
- 监控 API 调用日志，及时发现异常

### 2. 性能优化

- 合理设置访问令牌有效期
- 使用缓存减少 API 调用次数
- 批量处理数据操作
- 实现合理的重试机制

### 3. 用户体验

- 提供清晰的错误信息
- 实现无缝的授权流程
- 支持离线模式
- 提供同步状态反馈
