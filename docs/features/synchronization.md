# 同步功能

FlowUs Limbic 的核心功能是实现 Obsidian 与 FlowUs 数据库之间的双向实时同步。本文档将详细介绍同步机制。

## 同步原理

### 双向同步架构

FlowUs Limbic 采用双向同步架构：

```
┌─────────────┐         ┌─────────────┐
│   Obsidian  │◄───────►│   FlowUs    │
│   (本地)    │  双向   │  (云端)     │
└─────────────┘   同步  └─────────────┘
```

### 同步方向

1. **本地 → 远程**（Push）：将 Obsidian 中的变更推送到 FlowUs
2. **远程 → 本地**（Pull）：从 FlowUs 拉取变更到 Obsidian

## 同步策略

### 增量同步

为了提高效率，FlowUs Limbic 使用增量同步：

- 只同步自上次同步以来发生变更的项目
- 基于 `updatedAt` 时间戳判断变更
- 最小化 API 调用次数

### 同步间隔

您可以在插件设置中配置同步间隔：

- **最短间隔**: 10 秒
- **默认间隔**: 30 秒
- **最长间隔**: 5 分钟

> **提示**: 同步间隔越短，实时性越好，但会消耗更多 API 请求配额。

### 手动同步

除了自动同步，您也可以手动触发同步：

1. 打开插件设置页面
2. 点击"立即同步"按钮
3. 或使用命令面板中的 "FlowUs TODO: Sync Now" 命令

## 同步流程

### 本地 → 远程同步流程

```
1. 检测本地变更
   ↓
2. 收集变更的实体
   ↓
3. 转换为 FlowUs Block 格式
   ↓
4. 调用 FlowUs API 更新
   ↓
5. 更新本地同步状态
```

### 远程 → 本地同步流程

```
1. 调用 FlowUs API 查询变更
   ↓
2. 获取自上次同步以来更新的项目
   ↓
3. 转换为本地实体格式
   ↓
4. 合并到本地数据
   ↓
5. 更新本地同步状态
```

## 冲突解决

### 冲突检测

当本地和远程对同一项目都进行了修改时，会产生冲突。插件通过以下方式检测冲突：

- 比较双方的 `updatedAt` 时间戳
- 检查内容指纹（fingerprint）是否变化

### 冲突解决策略

您可以在插件设置中选择冲突解决策略：

| 策略 | 说明 |
|------|------|
| **远程优先** | 远程版本覆盖本地版本（默认） |
| **本地优先** | 本地版本覆盖远程版本 |
| **时间戳优先** | 较新的版本覆盖较旧的版本 |
| **手动选择** | 每次冲突时手动选择保留哪个版本 |

### 手动解决冲突

当选择"手动选择"策略时，发生冲突时会弹出冲突解决对话框：

1. 显示本地版本和远程版本的差异
2. 您可以选择：
   - 保留本地版本
   - 保留远程版本
   - 合并两者（编辑后保存）
3. 确认选择后继续同步

## 同步状态

### 状态指示器

插件会在以下位置显示同步状态：

- **TODO 视图右上角**: 显示当前同步状态
- **Obsidian 状态栏**: 显示简要状态
- **设置页面**: 显示详细的同步信息

### 状态说明

| 状态 | 说明 |
|------|------|
| ✅ 已同步 | 所有数据已同步 |
| 🔄 同步中 | 正在进行同步 |
| ⚠️ 待同步 | 有本地变更等待同步 |
| ❌ 同步失败 | 上次同步失败 |
| 📴 离线 | 网络不可用，使用离线模式 |

### 同步日志

您可以查看详细的同步日志：

1. 打开 Obsidian 控制台（`Ctrl/Cmd + Shift + I`）
2. 切换到 Console 标签
3. 查看带有 `[FlowUs Limbic]` 前缀的日志

日志包含以下信息：
- 同步开始/结束时间
- 同步的项目数量
- 任何错误或警告
- API 调用详情

## 离线模式

### 离线使用

FlowUs Limbic 支持离线模式：

- 没有网络连接时，您仍可以正常使用所有功能
- 所有变更会保存在本地缓存中
- 网络恢复后，插件会自动同步所有待处理的变更

### 离线数据存储

离线数据存储在 Obsidian 的插件数据目录中：
- 使用本地存储（Local Storage）
- 数据格式与远程保持一致
- 支持加密存储（可选）

### 冲突处理

离线期间可能产生的冲突：

- 离线时您修改了数据
- 同时 FlowUs 中的数据也被修改
- 网络恢复后，插件会检测并按策略解决冲突

## 性能优化

### 批量操作

为了提高同步效率，插件会：

- 将多个小的变更合并为批量操作
- 减少 API 调用次数
- 合理设置批量大小（默认每批 50 项）

### 智能重试

当 API 调用失败时，插件会：

- 自动重试（最多 3 次）
- 使用指数退避策略
- 429 限流错误会等待 `Retry-After` 头指定的时间

### 缓存机制

插件使用多级缓存：

- **内存缓存**: 最近使用的数据
- **本地存储缓存**: 同步状态和元数据
- **响应缓存**: API 响应（可配置 TTL）

## 同步限制

### API 限流

FlowUs API 有以下限制：

- **请求频率**: 最多 60 次/分钟
- **批量大小**: 每次最多 100 项
- **并发请求**: 最多 5 个并发

插件会自动处理这些限制，确保不会超出配额。

### 数据大小限制

- 单个 TODO 标题：最大 1000 字符
- 描述：最大 10000 字符
- 附件：不支持（计划中）
